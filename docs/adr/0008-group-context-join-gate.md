# ADR-0008: 成员加入走"群上下文门禁"——从群内打开分享链接才自动加入

## 状态
已接受

## 背景
PRD 把"加入群空间"列为 MVP 必须，但微信不提供"验证某用户是否真的在该群"的能力，
成员关系只能靠用户主动进入某个入口自证。ADR-0006 要求非成员不可见，因此"谁能加入"
直接决定了封闭性的强度。候选有：链接即入（打开分享链接就自动加入）、群上下文门禁
（仅从该群聊内打开才自动加入）、审批制（管理员同意）。

## 决策
- 采用**群上下文门禁**：用户在**群聊内**打开群空间/作品的分享卡片，小程序拿到
  `shareTicket` 并解密出 `openGId`，后端校验该 `openGId` 命中该空间后，**自动加入**
  成为成员（role=member）。
- 在私聊、朋友圈、群外转发等**无群上下文**的入口打开时，**不自动加入**，提示
  "请在群内打开后加入"，不返回内容。
- 空间**绑定唯一一个真实群的 `openGId`**（"一群一空间"）；已绑定 openGId 的空间，
  来自其他真实群的分享链接会被门禁拦截（避免一个空间被多个群共用）。
- 创建者建空间即成为 owner，无需经过门禁。

## 后果
- 封闭性是"软"的——拿到群内链接即可加入，但入口被限制在群聊场景，符合"基于微信群
  关系"的产品定位；放弃朋友圈/私聊转发的加入通道。
- 需处理 `shareTicket` 的解密链路（与 ADR-0001 的 openGId 辅助去重同源），并保证
  解密失败/无 shareTicket 时的降级文案。
- 已加入的成员在群外打开卡片仍可正常访问（校验的是成员资格，不是本次打开是否有
  群上下文）。

## 补充：作者退出群空间，既有投影保留
成员可自行退出群空间（member 软删），但**不撤销**其既有投影：作品仍是该群的沉淀内容，
对应"这颗星曾经闪耀过"。**作者身份独立于成员身份**——已退出的作者仍可编辑、撤销、
删除自己留在此群的作品，并参与互动。

## 补充：创建群空间与 openGId 绑定时机
- 创建群空间**仅需群名称**（必填）；封面可选（未传用默认占位）。创建者即 owner。
- 空间与真实群的 openGId 在**首次被群内打开**（shareTicket 命中该空间）时绑定；
  此前空间未绑定任何群，门禁在绑定后生效。

## 补充：群空间治理的 MVP 范围
- **owner 可改名、换封面**；**MVP 不做解散空间**（不可逆、低频率）。
- **成员名单对全体成员可见**（头像+昵称列表）；非成员不可见（ADR-0006）。
