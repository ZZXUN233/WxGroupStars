# ADR-0015: 草稿（Work.is_draft）——后端草稿而非本地暂存

## 状态
已接受

## 背景
发布页优化要求「编辑后支持保存草稿」。当时存在两种候选：前端本地暂存（存 storage，
不落库）与后端草稿（Work 表加 is_draft 字段）。草稿需要跨设备/跨会话可见、且未来可
接审核，前端本地暂存无法满足，且媒体直传 COS 后 key 需持久化。

## 决策
- **后端草稿**：Work 表新增 `is_draft`（默认 false）。`draft=true` 创建作品时不校验群、
  不投影；草稿仅在草稿列表（`GET /works/drafts`）与作者本人的 `GET /works/:id` 可见，
  对其他访问表现为不存在（NotFound）。
- **草稿 → 发布**：`PATCH /works/:id` 传 `draft=false` 与 `spaceIds`，更新作品本体后
  投影到所选群（已有投影则复活，与 ADR-0002 追加语义一致）。
- **保存草稿按钮**：发布页「存草稿」= `POST /works`（新建）或 `PATCH`（编辑）带 `draft=true`；
  「发布」按钮在新建/草稿态带 `spaceIds`，编辑已发布作品时不要求选群。
- **入口**：个人星轨页（查看自己时）提供「我的草稿」列表页，点击继续编辑。

## 后果
- work 表新增 `is_draft` 列；`getDetail` 增加作者校验分支。
- 媒体（已上传 COS key）随草稿保留，不因草稿态重复上传或清理。
- 草稿不计入 star-trail 作品数、feed 与时间轴（无投影自然排除）。
- 前端引入草稿态判断（isDraft），发布页按钮与群空间选择随之变化。
