# ADR-0018: 群空间申请审核 + 作品个人分享通道

## 状态
已接受

## 背景
ADR-0006 要求群空间完全封闭、ADR-0008 采用"群上下文门禁"加入。但现状有两处缺口：

1. **加入只有门禁、无兜底**：门禁依赖 `shareTicket → openGId` 解密（[spaces.service.ts](backend/src/spaces/spaces.service.ts) 仅当"传了 openGId 但不匹配"才拦截），
   **不传 openGId 的 join 直接放行**——任何登录用户可调用 `POST /spaces/:id/join` 混入任意空间。
   且微信生态决定了 openGId 只能覆盖"群内打开"场景，私聊/朋友圈转发的用户既无法自证同群、也无人审核。
2. **作品只有投影通道、无本体通道**：作品本体跨群唯一（ADR-0002），但 `GET /works/:id` 无成员校验，
   任何登录用户可读任一作品全文；而作者本人又缺少一种"不带群投影、直接分享给个人看"的方式。

## 决策

### 一、加入流程：门禁自动加入 + 申请审核兜底（双轨）
- 保留 ADR-0008 群上下文门禁：**群内**打开分享卡命中 openGid → **自动加入**（role=member, status=active），
  此路径为已验证同群，无需审核。
- **群外 / 无法验证**（无 shareTicket、解密失败、openGid 不匹配）的 join → 不直接加入，
  创建一条 **pending 申请**，待 owner/admin 审核后成为成员。
- 修复门禁绕过：join 必须携带空间上下文（openGid 或明确降级），不传 openGid 时一律走申请，
  不再自动加入。

### 二、成员状态模型（Member 表扩展）
- `Member` 新增 `status` 枚举：`active`（成员）/ `pending`（待审核）/ `rejected`（已被拒）。
  与既有 `role`（member/admin/owner）、`isActive`（软删除标记）并存：
  - `status` 表达**准入阶段**，`isActive` 表达**后续退出/被踢**（软删，投影保留，ADR-0008 补充）。
  - 迁移：现有 `isActive=true` → `status=active`；`isActive=false` 视为已退出，不参与申请流。
- 待审核成员不计入成员名单、不可见空间内容（ADR-0006 封闭性，仅展示中性占位 + 本人申请状态）。
- 拒绝后可重新申请（每次新 join 覆盖原 rejected 记录）。

### 三、审核与治理（成员管理）
- 审核主体 = **owner + admin**；owner 可指定/撤销成员为 admin。
- admin 权限边界：**仅审核申请 + 查看成员名单**；不能设 admin、不能踢人、不能转让 owner。
- owner 转让（ADR-0001）后，**admin 全部清空**，由新 owner 重新指定。
- 成员可自行退出、owner/admin 可踢出成员（软删 `isActive=false`，投影保留；被踢可重新申请）。
- 成员管理入口 = 空间详情页"成员管理"（owner/admin 可见），分"成员 / 待审核"双 tab；
  待审核项展示昵称+头像+申请时间，操作=通过/拒绝。

### 四、作品本体访问收紧
- `GET /works/:id` **收紧为仅作者本人可读**（发布页编辑回填场景，作者读自己的作品，天然成立）。
  不再存在"任何登录用户可读任意作品全文"的洞。

### 五、作品个人分享（不带投影）
- 作品本体仅属于作者；作者可发起**个人分享**：一条 `WorkShare` 记录（`workId` + 随机 token）。
- 持链接者**登录后**经 `GET /works/shares/:token` 查看只读页（标题+正文/媒体/作者），
  **无成员资格要求、不展示任何群信息、无点赞/评论/收藏**——与投影通道完全隔离（ADR-0002 互动属于投影）。
- 链接**长期有效**，作者可随时撤销（`isActive=false`）；撤销后可再生成新链接（新记录，旧记录失效）。
- 发起入口 = 作品详情页作者"管理"菜单 → "分享给个人"确认框 → 生成分享卡；
  分享页**纯只读**，不出现作者操作（撤销只在作品页管理菜单）。

## 后果
- 封闭性从"软门禁"升级为"门禁 + 人工审核"双保险：群内成员自动入群体验不变，
  群外/无法验证者走审核，owner/admin 把关；join 绕过洞被堵死。
- `Member` 表结构变更（新增 status 枚举）需一次数据迁移：现有 active 成员全部映射为
  `status=active`。
- 新增表 `work_share`（workId + token + isActive），长期有效链接的撤销靠 isActive 软删。
- 前端新增：空间页成员管理双 tab、作品页无权限态（中性标题 + 申请加入按钮）、
  个人分享只读页；修复 [app.tsx](frontend/src/app.tsx) 读 `spaceId` 而空间卡 path 用 `id`
  导致门禁不触发的 bug。
- 无通知系统：审核结果以"申请人重进空间页看到状态"承载（MVP 可接受，后续可加订阅消息）。

## 关联
- 依赖 ADR-0001（spaceId 主键 / owner 转让）、ADR-0006（封闭性基准）、
  ADR-0008（群上下文门禁 / 退出保留投影）、ADR-0002（投影为活实体 / 互动属于投影）。
