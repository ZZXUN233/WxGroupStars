# 《群星闪耀》微信小程序上线风险评估

> 版本：V1.0
> 日期：2026-08
> 范围：基于当前代码库（Taro 小程序 + NestJS 后端 + Prisma/MySQL + COS 存储）的上线风险盘点
> 结论导向：按"是否导致无法上线/被下架"分级，先给结论，再给落地动作

---

## 一、风险总览

| 级别 | 数量 | 含义 |
|------|------|------|
| 🔴 A 级 | 2 项 | 一票否决，必然拒审 / 下架，必须先解决 |
| 🟠 B 级 | 3 项 | 合规性硬伤，可能被要求整改 |
| 🟡 C 级 | 5 项 | 安全/稳定性风险，不影响上线但建议修 |

**一句话结论**：项目功能设计成熟、权限体系扎实，但 **UGC 内容安全审核完全没有落地**，配合外链 WebView、无协议无举报，属于"设计了好地基、墙没砌"的状态。**不补 P0 两项必被拒审；补完 P0+P1 大概率能过审。**

---

## 二、🔴 A 级风险（P0，必须先解决）

### 1. UGC 内容安全审核【完全缺失】—— 最致命

**现状**
- 产品是典型 UGC 作品社区（文字 + 图片 + 音视频 + 代码 + 外链 + 评论）
- `docs/adr/0014-content-safety-review.md` 明确写明"MVP 即接入微信文本 `msgSecCheck` + 图片 `mediaCheckAsync`"
- **但代码零实现**：
  - `backend/src/works/works.service.ts`（publish）直接写死 `reviewStatus: 'pass'`，注释自述"MVP 乐观展示（ADR-0014 图片异步审核回调再收敛）"——审核未实现
  - `backend/src/comments/comments.service.ts`（评论创建）无任何审核
  - 全局搜索 `msgSecCheck` / `mediaCheckAsync` / `contentCheck`：零实现命中
  - 图片走 COS 预签名直传，上传后无异步审核回调

**风险**
- 用户可发布任意文字 / 图片 / 评论，违规内容直接展示
- 这是微信小程序 UGC 类目的一票否决项，**必然导致拒审或上线后下架**

**落地动作**
- [ ] 文本审核：发布 + 评论接入 `security.msgSecCheck`，违规拦截
- [ ] 图片/音视频审核：接入 `mediaCheckAsync` + 配置审核回调地址，违规隐藏
- [ ] `reviewStatus` 由"乐观 pass"改为"pending，审核通过才展示"

---

### 2. 外链作品 + WebView 组合，高危内容通道

**现状**
- `works` 支持 `externalLink`（任意 URL 作为作品）
- 前端存在独立 `WebView` 页面（`frontend/src/pages/webview/index.tsx`）直接加载该 URL
- `WebView src={url}` 未做任何域名白名单 / 协议校验

**风险**
- WebView 可加载任意网页，**涉黄 / 涉政 / 赌博 / 钓鱼页面会通过小程序露出**
- 小程序对 WebView 跳转有严格限制，可被利用传播违规内容，**严重拒审风险**

**落地动作**
- [ ] WebView 增加**业务域名白名单**（需在小程序后台配置合法域名，WebView 仅允许配置的域名）
- [ ] 或限制 `externalLink` 类型（仅允许图文/视频白名单，禁止跳转任意网页）

---

## 三、🟠 B 级风险（P1，合规性硬伤）

### 3. 无用户协议 / 隐私政策 / 内容规范入口

**现状**
- 全项目未见《用户协议》《隐私政策》《内容规范》任何页面或强制确认

**风险**
- 微信要求收集用户信息（登录态、头像昵称等）必须有**隐私协议 + 授权弹窗**
- UGC 社区还需**用户协议确认**
- 缺失 → 审核要求补充，甚至拒绝

**落地动作**
- [ ] 新增《用户协议》《隐私政策》页面
- [ ] 首次登录 / 首次发布强制确认
- [ ] 开启 `wx.getPrivacySetting` 隐私授权弹窗

### 4. 无举报 / 投诉机制

**现状**
- 代码中无 report / flag 任何接口或前端入口

**风险**
- 微信社区类目强制要求提供**内容举报入口**（图文举报、侵权投诉）
- 缺失 → 审核要求补充

**落地动作**
- [ ] 新增作品 / 评论举报接口
- [ ] 前端增加举报入口
- [ ] 提供侵权投诉联系方式

### 5. 用户昵称 / 头像 = 新的 UGC 风险

**现状**
- ADR-0017 已实现头像昵称可自定义（`auth.service.ts` updateProfile）
- 但 `updateProfile` 零校验，**昵称可含违规词、头像可含违规图片**

**落地动作**
- [ ] 昵称并入文本审核通道
- [ ] 头像并入图片审核通道

## 四、🟡 C 级风险（P2，不影响上线但建议修）

### 6. 登录鉴权安全
- `auth.guard.ts` 每请求查 DB（性能，MVP 可接受，后续迁缓存）
- sessionKey 明文存 session 表（风险可控，但建议加密；安全性依赖 HTTPS）
- **dev 模式**（`WX_APPID` 未配置）固定 openid 登录——若误配上线所有用户共享身份，属**配置风险**，务必确保生产环境配置真实微信凭据

### 7. 邀请链接访问控制
- `acceptInvite` 走 token 即放行，无应用内审核（仅限 24h/一次性），可能被利用传播（风险次要）

### 8. 部署与 CORS
- `main.ts` CORS origin 硬编码 `gs.zzxun.cn` + localhost，前端域名变更需同步
- `credentials: true` 但 token 走 header（非 cookie），冲突不大

### 9. 群门禁依赖 shareTicket / openGId
- 群身份校验依赖微信 openGId 解密，openGId 只能覆盖"群内打开"场景
- 私聊 / 朋友圈转发走 pending 审核（ADR-0018 已兜底，设计合理）✅

### 10. 内容展示节奏
- 音视频 type 已支持上传，但未接媒体审核（ADR 规划 V2）——**未审核音视频比图片更危险**，建议 MVP 收紧或先过审

## 五、项目相对扎实的部分（风险已较好控制 ✅）

- **封闭群空间 + 申请审核双轨**（ADR-0018），成员范围可控
- **评论删除权限**：评论者本人或作品作者可删，已具备基础治理
- **软删除 + 审核状态字段留守**（`reviewStatus` 已在 schema），说明设计有意识，只差实现
- **权限体系明确**（owner / admin / member），越权检查较完整

## 六、落地优先级表

| 优先级 | 事项 | 动作 |
|--------|------|------|
| **P0** | 文本 + 图片审核 | 实现 `msgSecCheck` + `mediaCheckAsync`，违规隐藏/拦截 |
| **P0** | 用户协议 / 隐私 / 授权 | 增加页面 + 强制确认 + 隐私弹窗 |
| **P1** | 外链作品管控 | WebView 增加业务域名白名单，或限制外链类型 |
| **P1** | 举报 / 投诉入口 | 加作品/评论举报接口 + 前端入口 |
| **P2** | 昵称 / 头像审核 | 并入文本/图片审核通道 |
| **P2** | 内容规范提示 | 发布前强制确认 |
| **P3** | 性能 / 会话加密 | 会话缓存、sessionKey 加密存储 |
